Komponen Teknologi Rexa

Smart Inventory & Cash Flow Copilot · Tim ChibiRex · Agentic AI Hackathon 2026 · kondisi per 26 Oktober 2026

Ringkasnya: agent AI hanya memilih dan menjelaskan tindakan; angka dihitung oleh data (DuckDB dan model LightGBM), aturan dijaga oleh kode (guardrail di API), dan keputusan akhir tetap di tangan manusia (1-Click Approval sebelum PO masuk SAP). Semua bagian online berjalan di AWS, termasuk agent: laptop tidak perlu menyala saat demo.

Diagram arsitektur

Dashboard, Virtual HQ, API, guardrail, penyimpanan, tiruan SAP, dan agent berjalan di AWS. Laptop hanya dipakai untuk membangun data dan deploy; worker di laptop hanya cadangan kalau AgentCore bermasalah.

Guardrail di kode

GuardrailCara kerja
Filter 3σQty PO di atas target stok + 3σ permintaan dianggap lonjakan tidak wajar (misalnya pesanan borongan) → ditahan.
Batas PO harianTotal nilai PO per toko per hari maksimal Rp100 juta.
Circuit breakerKalau 3 PO ditahan guardrail dalam 60 menit, semua PO baru ditahan sampai manajer mereset.
Idempotency keyRequest yang diulang dengan kunci yang sama tidak membuat PO atau hold ganda.
Draf secara defaultAgent hanya menyusun draf; PO baru masuk SAP setelah manajer menekan 1-Click Approval. Satu draf per SKU.
Data ConfidenceKalau data stok tidak bisa dipercaya (di bawah 0,8, misalnya ada selisih hitung fisik), PO ditahan sampai stok diaudit.
Syarat Hold ReorderReorder hanya boleh ditahan kalau penjualan turun dan jenis produknya tidak komplementer; 10% tetap dibeli sebagai stok uji (exploration budget).

6. Alur satu klik (yang ditunjukkan saat demo)

1. Manajer klik "Jalankan Agent" di dashboard atau di Virtual HQ (Amplify)
↓
2. API di Lambda mencatat tugas ke antrian: status MENUNGGU (SQLite di EFS)
↓
3. Dashboard meminta Lambda Copilot membangunkan agent di Bedrock AgentCore (InvokeAgentRuntime)
↓
4. Agent di AgentCore mengambil tugas: status BERJALAN; Claude Sonnet 4.6 mulai berpikir
↓
5. Agent memanggil tools di API: Plan → Reason → Act (prioritas, cek substitusi, hold, draf PO)
↓
6. Guardrail di API memeriksa setiap aksi; yang melanggar ditahan (DITAHAN_GUARDRAIL)
↓
7. Setiap langkah tampil langsung di dashboard; ringkasan agent = Review (±27 detik dari klik)
↓
8. Manajer klik "1-Click Approval" → API mengirim PO ke tiruan SAP → nomor PO 45xxxxxxxx

Langkah 4–7 adalah loop agentic yang diminta juri (plan, reason, act/tool, review). Langkah 8 adalah human-in-the-loop: tanpa persetujuan manajer, tidak ada PO yang masuk SAP.

7. Dari laptop ke AWS

Rencana awal memakai Amazon Bedrock. Pada 22 Oktober, kuota token Bedrock untuk model Amazon Nova di akun tim bernilai 0, jadi LLM sementara berjalan di laptop (Ollama) lewat worker yang mengambil tugas dari antrian API. Pada 25 Oktober Claude di Bedrock bisa dipakai, dan LLM pindah ke Claude Sonnet 4.6. Pada 26 Oktober agent sendiri dipindah ke Amazon Bedrock AgentCore Runtime, sehingga laptop tidak perlu menyala saat demo.

Kode agent sama di ketiga tahap; yang berubah hanya tempat menjalankannya, jadi dashboard dan API tidak perlu diubah. Agent dibangunkan lewat Lambda Copilot karena Lambda API di VPC tidak punya akses internet keluar dan browser tidak punya kredensial AWS. Worker di laptop tetap bisa dinyalakan sebagai cadangan.
